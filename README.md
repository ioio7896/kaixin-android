# 开心离线输入法

开心离线输入法是一款给 Android 手机用的中文输入法。它可以在没有网络的情况下打字，词库和表情资源随应用一起安装。

## 能做什么

- 拼音输入：中文 26 键、九宫格和小鹤双拼
- 手写和笔画输入
- 英文、数字、符号和 Emoji 输入
- 简体、繁体切换，以及常用词联想
- 自定义词库、常用词学习和剪贴板历史
- 键盘高度、主题、按键声音和震动等设置

## 0.5.5 数字键盘和九键功能区

- 数字键盘统一为四排四列，0 固定在 8 下方，与 2、5、8 同列；各数字键等宽等高，不再把 0 放到右侧或单独增加底栏。退格固定右上并支持按住连续删除，确认键固定右下，按输入框显示完成、下一项、搜索、发送或换行。
- 普通数字页采用 `1 2 3 退格 / 4 5 6 符号 / 7 8 9 空格 / 返回 0 . 确认`。运算符通过符号页输入，取消数字页重复的中英切换。
- 整数页不显示小数点和空格；小数页保留小数点，有符号页提供负号。电话页数字区末排为 `* 0 #`，长按 0 至少 800 毫秒输入 `+`，返回移至右侧第三排。日期页提供 `/` 和 `-`，时间页提供 `:`，日期时间页同时提供三种分隔符；数字的位置不随场景改变。
- 数字按字符串直接上屏，保留前导 0。返回恢复进入数字页前的中文、英文或笔画键盘，并保存返回布局；切换输入框时根据新的字段类型重建数字页。
- 九键右侧采用较大的退格、“清空拼音”和“分隔”。清空拼音使用较轻的视觉样式，清除未上屏内容、读音锁定和光标状态，不删除宿主文字。“分隔”在当前组合位置插入拼音分隔符，禁止开头及连续分隔；九键查询保留分隔边界，候选展开仍使用候选栏入口。

## 0.5.4 拼音搭配、整句与可选纠错

- 新增独立的 `app/src/main/assets/language-model/collocations.tsv` 日常搭配种子。权重为人工编辑的支持值，不是真实语料频次；仅关联已有词库词，不新增词条，也不使用 vivo 的代码、模型或词库。原有长词切分搭配作为较弱线索，与种子一起按前词的条件支持度校准，每个前词最多保留 64 个后继。
- 后台候选补充同时召回个人上下文和基础搭配中的匹配词，最多检查 24 个词；基础搭配参与统一评分。首批只读取已经缓存的基础上下文，不新增这部分数据库查询。设置中的“常用搭配辅助选词”可独立关闭，个人学习仍按原有开关工作。
- 候选排序先保护完整词库匹配，再比较简拼、混拼与组句；纠错排在正常完整匹配之后、不完整补全之前。同组继续综合词频、匹配代价、个人偏好和上下文评分，纠错保留独立惩罚值。
- “26键完整拼音组句”默认开启，“9键完整读音组句”默认关闭。组句只在后台补充阶段搜索 5–24 个完整音节；九键需要完整编码或全部锁定读音。每条结果最多 8 个词，限制冷门词、无搭配支持的连接和单字堆叠；已有词库词与组句分别保留来源。关闭组句不影响原词库长词。双拼保持原词库匹配方式。
- 新增默认关闭的拼写纠错、按键触点纠错和模糊音开关。只用于 26 键全拼、4–32 个输入字符的多字词；拼写和触点纠错在缺少高频完整匹配时补充，模糊音需另选音组。只尝试一次变化，最多查询 27 个变体、补充 6 个候选，且不与整句组合纠错。触点只保留在内存中，候选选中后才上屏；学习使用候选的正确读音。
- 个人上下文在非汉字上屏、会话切换或连续输入超时后断开，避免跨句、跨输入框拼接学习。同步更新词库数据库版本。

## 内置词库来源

`lexicon/` 完整镜像桌面项目的 `lexicon/` 目录，中文、英文、分类词和热词均直接使用桌面项目的原文件，安装包内的拼音数据库由这些文件生成。更新镜像时运行：

```powershell
python tools/sync_desktop_lexicon.py --source '<桌面项目目录>\lexicon' --target lexicon
```

`data_sources/desktop_single_char_readings.txt` 是从桌面项目的 8105 字表、固定版本拼音数据及读音修订生成的构建辅助索引，不增加其他词语；更新桌面字表时使用 `tools/import_desktop_character_readings.py` 重新生成。

2026-10-18 已将桌面项目的 119 个词库文件完整同步到本目录，并重新生成 8105 字的读音辅助索引。APK 构建使用本目录镜像，安装后的离线查询不依赖电脑上的源目录。

安卓专用的候选修正规则位于 `app/src/main/assets/lexicon-corrections/`。它保留桌面词库原文件，降低冷门扩展词的默认权重，并把三个放错类别的词移入对应修正词表；基础词库中同词条的较高权重仍有效。

词库规则支持按来源路径前缀设置百分比权重，最长匹配前缀生效，再应用来源和逐词上限；构建数据库与应用内原始词表回退使用相同规则。候选召回为精确词及常用短词保留少量名额，补充阶段可从本地上下文记录中补入符合当前拼音的词。首批与完整结果的首位不同时，完整结果至少等待首批发布 120 毫秒再发布；性能日志开启后只统计换位次数，不记录输入内容。`tools/evaluate_candidate_ranking.py` 从拼音数据库的读音表评估首选、前五缺词、未召回及首批换位；它不覆盖整句、纠错、触点修正和实时个人记录。

## 0.5.2 键盘性能优化

- 自动学习按受影响的拼音、简拼、混拼及九宫格索引项更新；后台积压的选词任务每批最多合并 32 项，批次统一生成加密快照。序列化、加密和持久化不再持有词典实例锁，保存与清除/外部编辑按修订号核对，避免旧快照恢复已删除记录。
- 学习后按词语和读音失效召回及界面候选缓存，包括此前没有召回新词的输入；无关查询继续执行。受影响查询保留上一帧显示，等待新结果时禁止选择旧候选。双拼界面和造词查询采用保守刷新。
- 首批查询采用 24ms 软预算：完成必要的精确召回后，可提前结束简拼扫描或推迟前缀扩展，补充阶段继续完整查询。该值不是实际延迟保证；限时结果不写入完整结果缓存。
- 首批与补充阶段在同一查询内复用只读词库的数据库行；较大的召回额度只读取缺失尾部，空结果也可复用。每次查询最多保留 16 组、估算 256 KiB 中间数据，取消后随查询释放。
- 候选栏按槽位更新，只隐藏多余项；展开候选按可见行索引绑定，保留按下状态和无障碍焦点保护。
- 字节预算查询缓存共享 8–24 MiB 总额度，按设备内存配置；优先回收派生候选及整句缓存，保留基础召回。系统内存紧张时分级回收。此额度不包含模型、数据库页缓存、全部界面或应用总内存。

遵循项目约定，不运行代码测试；仅进行源码审阅和 Debug 编译打包，实际性能收益尚未实测。

## 0.5.1 键盘按钮比例

- 简拼、全拼及混拼候选中，基础词频达到 4000 的二、三字中文词在完整匹配候选中优先排列；同组仍按词频、个人习惯和上下文综合排序。用户置顶、单音节单字优先及完整匹配优先规则继续生效，部分匹配和纠错词不获得此优先级。
- 输入三个字母时，符合完整简拼或混拼输入的高频二字词优先于高频三字词；数据库召回、首批候选及最终排序采用相同规则，避免三字词热度挤掉二字词。

- 中文底排按符号 12%、数字 15%、空格 42%、中英 13%、回车 18% 分配扣除间距后的宽度；英文底排保留词/字切换，空格占 40%、回车占 18%。邮箱和网址快捷键遵循相同比例。
- 26 键四排使用相同的高度权重；Shift 和退格为 1.5 个字母键宽度，第二排保持半键缩进，并修正间距造成的字母宽度差异。
- 九宫格数字区与右侧功能列按 78:22 分配，窄屏同步缩小拼音路径栏。窄屏和单手模式减少横向间距，保留各排高度。
- 数字、符号及面板底排统一使用竖屏 54dp、横屏 44dp 的行高，空格和回车分配更大宽度。实际按钮视觉高度扣除上下间距，间隔触点由相邻按键接收。
- 手写底排按撤销 22%、清空 18%、返回 18%、空格 22%、回车 20% 分配；按钮缩短文字并保留完整操作及无障碍说明，底排使用固定高度。手写等面板释放未使用的拼音路径行，增加内容空间。

自定义总高度、字体和间距继续生效；过大的旧间距值限制为单边最多 3dp。候选栏继续采用默认 48dp 和用户字号适配，工具栏图标保持 40dp 视觉尺寸及完整单元触摸区域，输入时与候选共用固定高度，避免键区跳动。按项目约定未运行代码测试。

## 0.5.0 扩展字集和连续多字手写

- 新增内置 [PP-OCRv5 Mobile](https://huggingface.co/PaddlePaddle/PP-OCRv5_mobile_rec) 识别模型，字符表有 18,383 项，其中 15,907 项为汉字，原生覆盖简体、繁体和部分生僻字。扩展模型约 7.86 MiB，继续使用离线 NCNN CPU 推理；常用字模型和笔画字典保留为补充。
- 手写面板点“单字/连写”切换模式。连写时从左向右写一行，最多识别 12 个字符；停笔后显示整段候选，点击候选一次性上屏。默认连写模式和停笔等待可在设置中调整。
- 字界不清时，写完一个字点击“分字”，再写下一字，按标记逐字识别并组合候选。撤销笔画时同步撤销失效字界。
- 连写识别后显示逐字预览，点击某个字可从识别候选改选或删除。造词补字流程保持逐字确认读音。
- 采用有限宽度的 CTC 前缀搜索产生整段候选，并正确处理重复字之间的空白；结果仅在内存中保留，继续书写、模式切换、撤销和清空会取消过期结果。
- 繁体识别结果可按中文输出设置转为简体，简体也可转为繁体。双向转换使用随 APK 打包的 OpenCC 字典。

扩展字符表不覆盖所有 Unicode 汉字。当前支持横向单行连写，竖排、跨行和高度重叠的书写请用分字或单字模式。按项目要求未运行代码测试、识别评测或实机验证；字符表覆盖数量不代表准确率。

## 0.4.1 离线手写模型

- 内置 [Ismantic/Handwritten](https://huggingface.co/Ismantic/Handwritten) MobileNetV2 INT8 模型，识别 3,755 个 GB2312 一级汉字；模型约 4.1 MB，首次使用无需联网下载。使用 NCNN 在后台进行 CPU 推理。
- 白底黑字笔迹先裁剪、等比缩放、居中，再按上游共享 C 预处理规则转为 64×64 输入。识别不依赖键盘配色，字形模型不要求固定笔顺。
- 模型前 12 个候选优先，模板和笔画索引补充候选，最多显示 20 项并去重；模型加载失败时显示后备状态。繁体输出仍由 OpenCC 转换，本模型并非原生繁体识别模型。
- 继续书写、清空、撤销或退出面板时取消过期结果；退出后在工作线程释放模型。增加识别状态、低置信度提示、点状笔画显示，最多支持 64 笔。
- 权重、字符表与许可证随 APK 打包，构建时校验发布文件 SHA-256；无需安装其他手写应用，不保存或上传笔迹。

当前适合逐字书写；生僻字仍依靠笔画后备候选。未运行代码测试、识别评测或实机验证，因此不承诺本应用的准确率或延迟达到模型发布方的评测数字。

## 0.4.0 键盘优化

- 拼音路径按音节长度降序、同长度按 A–Z 排列；九宫格补充已输入编码可匹配的长音节。已选读音用勾选标记，支持只解锁当前音节、保留其他限定，以及原文上屏。
- 候选综合词频、匹配质量、个人偏好和上下文评分，整句按词数归一化；完整匹配优先于部分输入，候选绑定输入框会话，短输入减少触点纠错。
- 退格、光标移动按系统 Unicode 字符簇处理；按词删除使用中文词边界，单次最多 16 个字符簇。最近一次可记录的文本编辑支持撤销和重做，仅保留在内存中，并核对输入框与文本。
- 回车先确认正在输入的拼音，再次点击执行发送、搜索或换行。邮箱、网址、电话、整数、小数和负数使用对应布局。
- 左右单手模式使用实际窗口宽度，不缩小字体和按键高度；浮动键盘支持拖动、调宽调高、方向分别记忆位置和恢复停靠。宽屏可开启分离式字母键布局。
- 明暗模式支持跟随系统；增加高对比度、紧凑/标准/大字预设、横屏独立高度与逐项重置。候选文字放大时同步增加行高。
- 表情支持离线中文关键词、英文 Unicode 名称和直接字符搜索；部分手势表情长按可选肤色。图片异步解码、使用系统字形占位，并有缓存预算及内存回收。
- 符号增加最近使用；剪贴板增加完整内容预览、字数和保留期限提示；词库导入可合并或覆盖同名词。
- 手写支持可调停笔等待，继续书写或撤销时取消旧识别结果，并改善笔迹采样和无结果提示；0.4.1 已在此基础上接入内置神经网络模型。
- 隐私模式暂停学习和历史记录，清理临时编辑状态；已有剪贴板历史只有主动清空才删除。内部关键词搜索不学习输入。
- 词库数据库以确定性的 gzip 文件打包，安装时流式解压；保留原始词库作为离线回退。性能日志按界面、首批候选、完整查询等阶段分别设置耗时预算。

撤销仅在宿主提供可核对的有限文本快照时使用输入法内部记录，否则尝试宿主原有撤销。字符簇规则使用设备系统 ICU；旧 Android 的 Unicode 数据可能不包含最新表情序列。

## 从源码构建

需要 Android Studio、Android SDK、NDK 27.2.12479018、CMake 3.22.1 和 Python 3。NCNN 预编译依赖保存在 `third_party/ncnn/`，恢复方式见该目录说明。用 Android Studio 打开项目目录并构建 Debug APK，或在 Windows PowerShell 中运行：

```powershell
.\gradlew.bat :app:assembleDebug -x test -x connectedAndroidTest
```

APK 默认生成在：

```text
build/offline-ime-app/outputs/apk/debug/app-debug.apk
```
